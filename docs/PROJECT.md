# BlockPulse 项目说明

**一边等结果，一边交易整个过程。**BlockPulse 把红黑绿轮盘的揭晓悬念、交易所的多空交易和量化策略放进同一局游戏：围绕一个事件形成判断，把判断变成持仓，再随着事件进展和市场报价调整选择。

这个想法来自一个直观感受：传统押注往往是“选一个结果，然后等开奖”，等待过程能做的事情很少。我们想让这段等待也热闹起来。你可以追热门、押冷门，觉得某色被高估时反手买 NO；报价变化了，可以继续持有，也可以在封盘前兑现或离场。越临近揭晓，每一次选择越有分量。

**我们想让每个有趣且有明确结果的事件，都能成为一场可交易的游戏。**有人相信结果，有人交易波动，有人让规则策略参与。不同判断汇入同一个市场，共同改变份额报价，最后由独立事件揭晓红、黑、绿谁赢。这是黑客松期间从临时灵感赶出来的原型，也是一套仍能继续生长的玩法。

## 乐趣来自哪里

- **热门在涨，要追还是要反手？**买入、卖出、NO 和平 NO 都会影响报价。押对方向之外，你还要判断当前的入场价格是否值得。
- **冷门翻盘，悬念一直留到揭晓。**你可以低价买入受冷落的结果；如果独立事件最终命中这一色，这些份额一样按每份1积分兑付。低价入场与最终命中的组合，让反转有了具体的回报。
- **先退出，也是一种玩法。**在交易窗口内，玩家可以卖出持仓兑现波动，或判断变化后减仓离场；也可以留到封盘，等待最终结果。
- **让策略加入这场拉扯。**练习场可以让价值或动量策略执行 YES 买卖，与你的手动操作和本地 Bot 一起形成动态报价。策略会成交，也可能看错。
- **疯狂来自判断的碰撞。**一个结果被追捧、另一种判断开始买入 NO、原有持仓选择卖出，报价就会持续变化。未来更多玩家与策略加入时，这种来回交锋可能产生密集订单，让每一局拥有自己的节奏。

## 从入场到再玩一局

**选事件 → 判断方向 → 买卖多空 → 策略参与、调整仓位 → 提前退出或封盘结算 → 再玩一局。**

1. **选一局事件。**从事件入口进入，先看清预测什么、何时截止，以及红黑绿各自代表的结果。
2. **把判断变成持仓。**买入你看好的颜色，或者买入 NO 押某色不会命中，同时查看成交成本和命中回报。
3. **交易整个过程。**观察事件与份额报价，决定加仓、卖出、调整方向；在练习场也可以启用规则策略，让它按配置执行买卖。
4. **选择怎样结束这一局。**封盘前可以退出持仓；持有到封盘的份额等待独立事件结算，命中的颜色每份兑付1积分，其他归零。
5. **看结果，再作新判断。**查看成交记录与含费净盈亏，复盘自己的入场、退出和策略，再开始下一局。

## 一局预测什么

- **本地练习**：独立模拟 SOL/USD 价格，60秒一轮，通常55秒交易、5秒封盘。价格随机序列与订单和策略随机序列隔离，修改交易行为不会改变同一种子下的最终事件。
- **真实 SOL/USD**：Coinbase Exchange SOL-USD 指定一分钟K线收盘价。准备时固定参考、上下各2基点（±0.02%）区间、UTC目标时间及提前15秒的截止。到期10秒后只读取精确目标分钟的 close，不用最新 ticker 代替。

红：末价高于上界；黑：低于下界；绿：上下界内，含两端。真实数据不可用时显示等待或重试，不随机补结果、不更换目标。真实行情场次暂只保存在当前页面，刷新丢失。

“独立”指与本局订单无因果关系；单一外部交易所行情仍有操纵、可用性和数据修订风险，当前不宣称绝对公平或经合约验证。离线种子与状态可被客户端读取，练习场没有对抗性防作弊保证。

## 玩家操作与收益

| 操作 | 实际持仓变化 | 目的 |
| --- | --- | --- |
| 买入红 YES | 增加红份额 | 押红命中或盘中上涨 |
| 卖红 | 减少已有红份额 | 提前兑现或止损 |
| 买入 NO 红 | 原子买入等量黑、绿 | 押红不会命中 |
| 平 NO 红 | 原子卖出等量黑、绿 | 退出空头组合 |

四种操作在同一 LMSR 和积分账本中计算，每条交易腿收取0.3%费用。NO 是全额支付的另两色组合，无借贷、杠杆或强平；一腿失败整单拒绝。每份赢家兑付1积分，其他0。份额价格与条件回报不是客观胜率。

例如100份均价0.10买入成本10：若选择均价0.30卖出，到账30；若选择一直持有且最终命中，兑付100。这是两种不同退出路径，示例未计费用，实际报价包含滑点。持有到期未命中则兑付0，策略也可能亏损。

## 量化策略如何参与

当前练习场提供价值与动量两种规则策略，用玩家自己的积分执行 YES 买入和卖出，并记录判断理由与成交。玩家可以配置每单份额、仓位上限和判断阈值；策略在封盘时停止。NO 和平 NO 目前由玩家手动操作，自动策略尚未覆盖这两类订单。

真实 SOL/USD 模式暂禁用自动交易，避免把尚未校准的模型当作真实行情策略。这里的“量化”是规则驱动的交易自动化，策略仍可能产生亏损。

策略竞争是后续值得探索的方向：当更多玩家和策略围绕同一事件反复报价、交易与退出，可能产生大量订单，从而形成对低延迟与并发处理的实际需求。目前的2或20个本地 Bot 用于演示市场互动，尚不能证明链上吞吐能力。

## 公平性与记账保护

- 订单不能改变事件路径、来源、上下界和截止，既不能刷笔数抬高结果，也没有游戏内加减结算分数的入口。
- 本地剩余合法变化范围若已确定同一结果，提前封盘；真实截止或已知结果在引擎层拒绝订单，包含NO与平仓路径，不能只依赖按钮禁用。
- 不因模型概率四舍五入成100%而封盘，也不随行情改写LMSR先验或已有持仓成本。
- 自买拉价不能伪造已兑现利润。采用含费用、考虑逐腿价格影响的清仓估算；现金和储备守恒，所有可能兑付需有资金覆盖。
- 练习场的玩家策略用自己的资金实际成交、展示理由和记录，封盘自动停止。真实行情暂禁用未校准自动交易。策略可以亏损，不读未来结果。

| 能力 | 新积分预测玩法 | 既有 MON 合约演示 |
| --- | --- | --- |
| 买入卖出、动态报价 | 已实现 | 已保留，需钱包与合约地址 |
| NO 与按预算交易 | 已实现 | 尚未接入 |
| 独立价格事件 | 模拟 / 公开 SOL/USD 行情 | 尚未接入，仍为旧热度与哈希规则 |
| 玩家策略与净盈亏排名 | 策略限练习场；两个事件均支持净盈亏排名 | 尚未接入 |

积分和测试网 MON 账本独立，新价格事件没有自动上链。未提供公开多人、撮合服务、身份防刷、杠杆永续或生产可验证预言机。既有 MON 合约仍使用旧热度与哈希规则，不能据此宣称新版独立事件玩法已经在链上运行。

## 事件与玩法的扩展方向

我们的设想是：**只要找到一个有趣、结果能够核验的事件，就有机会把它做成这套系统里的新玩法。**事件需要预先明确数据来源、观察时间、结果划分、截止时间以及异常处理，才能让不同玩家围绕同一套规则交易。

当前只有离线模拟价格和真实 Coinbase SOL/USD 两个预设入口，不支持用户任意文字创建事件或自定义参数。后续可以逐步探索：

1. **更多事件模板。**先将可核验的数据整理成模板，再开放按模板建房；不同事件可以采用不同的结果区间与节奏。
2. **共享房间与策略竞争。**让真人和策略进入同一个市场，补齐统一时钟、订单顺序与可回放记录，再测量真实并发和延迟。
3. **更丰富的交易策略。**探索自动 NO、止盈止损、策略参数与回测，让玩家能表达更多判断；每种机制都需说明成本和退出条件。
4. **事件结算上链。**将固定事件规格、数据证明、截止与兑付迁入合约，让结果与资金流向可以核验。

这些是扩展方向，尚未全部实现。当前原型先把“事件揭晓的悬念 + 盘中交易的选择 + 策略之间的互动”做成可玩的一局，再通过试玩打磨节奏和规则。
