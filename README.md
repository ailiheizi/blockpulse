# BlockPulse · 链上交易竞技游戏原型

判断红、黑、绿哪种结果会发生，按预算买入结果份额，盘中卖出或持有到期。本地积分模式加入 NO 做空组合、按预算下单和同预算收益对比；完整项目定位见 [项目说明](docs/PROJECT.md)。

页面有两种交易资产，在首页顶部切换：

- **模拟积分**：本地浏览器模拟，含策略 Bot 与繁忙模式，无需钱包，积分不可兑换。
- **测试网 MON**：用钱包里的 Monad 测试网 MON 直接和链上市场合约交易。买入把 MON 转入合约，卖出与兑付由合约转回钱包，每笔都需钱包确认并支付 gas。链上模式没有 Bot，市场由所有连接同一合约的钱包共享。

测试网 MON 没有价值，不能兑换为游戏积分，两种模式的账本互相独立。成交频率来自本机模拟或你自己的链上操作，不代表 Monad 链上 TPS；链上结算使用的随机数取自区块哈希，出块者可以施加影响，仅适合测试网演示。

页面资源使用本地文件和系统字体，不加载外部 SDK。只有主动连接钱包、点击“读取测试网”或使用链上模式才会读取链数据；不使用这些功能时，本地交易仍可离线试玩。

## 直接试玩

双击项目根目录的 **本地试玩.html** 即可离线体验交易。样式和脚本全部内联，无需 Node.js、终端、安装依赖或上传项目。钱包扩展通常需要 HTTP / HTTPS 页面才能注入，测试钱包接入请使用下面的本地服务。修改源码后用 `npm run build:local` 重新生成单文件。

通过本地 HTTP 开发时，macOS 可双击 **启动试玩.command**。它会复用已运行的本项目服务，或使用系统 Node.js / 本机已有的 Codex Node.js 运行时启动，再打开 [本地试玩](http://127.0.0.1:4173/)。提供服务的终端必须保持打开，按 Control+C 才停止；不安装依赖、不关闭其他进程、不发布站点。

也可以在终端运行：

```sh
cd "/你的本地目录/blockpulse-demo"
./启动试玩.command
```

终端已配置 Node.js 18 或更新版本时，可运行 `npm start`。服务只监听 `127.0.0.1:4173`。`dist/index.html` 使用模块，需通过 HTTP 运行；可直接双击的是项目根目录的 `本地试玩.html`。

## Monad 测试网接入

1. 在支持 EVM 的浏览器钱包中打开本地 HTTP 页面，点选钱包卡片，再点击对应的连接按钮授权账户。支持 EIP-6963 多钱包发现，也兼容传统 `window.ethereum` 注入。卡片支持键盘单选，只展示实际检测到的钱包；账户地址和余额在连接后展开。
2. 若当前网络不匹配，点击“切换到 Monad Testnet”。仅在钱包提示未添加该网络时请求添加，添加后再次切网并核对实际链 ID；拒绝请求不会影响本地游戏。
3. 连接步骤会标明账户、网络和余额是否就绪。连接后可单独“刷新余额”、查看读取时间、复制地址或打开地址浏览器；剪贴板不可用时会展开可手动复制的完整地址。切换账户或网络会清除旧余额并重新读取；断开本站连接后不再跟踪该钱包，扩展中的网站授权仍需在钱包内管理。
4. 无需钱包也能点击“读取测试网”，先核对 RPC 的链 ID，再读取最新区块、高度、区块时间和 RPC 请求耗时。成功后每 5 秒采样一次，保留最近 6 个不同区块的快照；这不是连续区块列表，也不是链上 TPS。切到后台或浏览器离线时暂停，返回或联网后恢复；读取失败则停止自动重试，保留旧数据并标明非实时状态，可手动重试或暂停。
5. 收起接入面板会暂停区块读取，让出交易空间；再次展开不会自动恢复读取。没有钱包、钱包不支持自动添加网络时，可展开“手动添加网络 / 连接帮助”，查看网络参数并复制 RPC。
6. 需要测试币时，使用面板里的“免费领取测试网 MON”：列出官方与多家第三方水龙头，连接钱包后可一键复制地址；余额不足 0.05 MON 时会提示。链接均在新标签页打开，本站不代领、不保存地址。各家额度和条件会变，以对方页面为准（2026-10 核对：QuickNode 免账号免主网余额、每地址 12 小时一次；Alchemy 约 1 MON / 24 小时，需地址持有少量以太坊主网 ETH；官方水龙头偶有限流）。

| 配置 | 值 |
| --- | --- |
| 网络 | Monad Testnet |
| Chain ID | `10143` / `0x279f` |
| 原生测试币 | MON，18 位小数 |
| 公开 RPC | `https://testnet-rpc.monad.xyz` |
| 区块浏览器 | [Monadvision Testnet](https://testnet.monadvision.com) |

网络参数依据 [viem 官方链定义](https://github.com/wevm/viem/blob/main/src/chains/definitions/monadTestnet.ts)，浏览器使用其原浏览器域名重定向后的 Monadvision 地址；钱包接入参考 [Monad 官方说明](https://docs.monad.xyz/guides/add-monad-to-wallet/testnet)。公开 RPC 可能限流或不可用，面板会显示失败，本地模拟可继续。

模拟积分模式只请求账户授权、网络切换和链上只读数据，不请求消息签名或发送交易；链上 MON 模式才会请求 `eth_sendTransaction`，并且每一笔都由钱包单独确认。钱包地址和余额不写入本地游戏存储；公开 RPC 只接收链 ID 与最新区块查询，余额查询通过用户选择的钱包完成。

钱包图标仅接受钱包声明的、有大小限制的 `data:image` 数据图像，通过独立的 `<img>` 加载，不插入 SVG 标记或访问外部图床。无法加载图标时显示文字占位，钱包名称和图标不作为身份验证依据。图标处理遵循 [EIP-6963 的安全要求](https://eips.ethereum.org/EIPS/eip-6963#prevent-svg-javascript-execution)。

钱包的每次只读状态请求有 8 秒超时，失败后可重试或断开重连；等待用户授权或确认切网的弹窗不受这个超时限制。迟到的请求结果不能覆盖新账户、新网络、暂停后的数据或重新读取的结果。区块采样和钱包余额刷新相互独立，刷新余额不会开启公开 RPC 轮询。

## 链上市场合约

[`contracts/src/BlockPulseMarket.sol`](contracts/src/BlockPulseMarket.sol) 是一个共享的三结果 LMSR 市场：每份命中兑付 0.001 MON，手续费 0.3% 留在做市储备，单笔 1–1,000 份，每个地址每轮 3 张行动券，全场热度最多偏离 ±9。开局时登记一个约 57 秒后的随机区块，结算噪声取自它的哈希；超过 256 个区块无法读取时，合约重新登记而不会结算。做市储备覆盖所有可能兑付，合约余额始终等于做市储备加待领取兑付。

使用方式：

1. 切换到“测试网 MON”，连接钱包并切到 Monad Testnet。
2. 在“链上市场合约”里粘贴已有合约地址，或用钱包部署新市场（初始储备至少 0.02 MON，你成为管理者，只能在回合之间取回储备）。页面会比对链上代码与内置合约完全一致才使用，并可复制 `?market=0x…` 分享链接，让其他人进入同一个市场。
3. 任何人都可以开局、交易、行动和结算；买入时多付 3% 作为价格保护，未用部分由合约当笔退回，卖出设置 3% 最低到账保护。

合约没有由本仓库代为部署，默认不带地址（`DEFAULT_MARKET_ADDRESS` 为空）。要让线上页面直接可用，请自行部署后把地址写入 `dist/monad-market.js` 重新发布。

**已知风险，尚未在真实测试网验证**：Monad 的[储备余额规则](https://docs.monad.xyz/developer-essentials/reserve-balance)规定非发送方账户的执行后余额不得低于 min(交易开始时余额, 10 MON)，文档没有写明合约账户是否适用。若适用，余额低于 10 MON 的合约在卖出、领取或取回时会回滚（gas 照扣）。本地 anvil 不执行这条规则，所以本地测试通过不能证明测试网一定可用。遇到回滚时，把做市储备注资到 10 MON 以上再试；另外，余额低于 10 MON 的钱包只能每 3 个区块转出一次 MON，页面在连续买入前会自动等待。

用 Foundry 本地离线编译和测试（需要本机已有 solc 0.8.30，不会联网）：`npm run test:contracts` 跑 13 项合约测试，`npm run build:contract` 重新生成 `dist/monad-market-artifact.js`。

后续黑客松版本可以继续推进：接入可验证的随机源；按房间隔离状态并测试多房间并发与实际链上吞吐；把 Bot 做成链上或链下的真实参与者。

## 主题切换

顶部的主题按钮在“跟随系统 → 浅色 → 深色”之间循环，偏好保存在浏览器本地，页面加载前就应用以避免闪烁。深色样式是唯一来源，浅色由 `npm run build:theme` 从 `style.css` / `monad.css` 的颜色自动生成 `dist/theme-light.css`；修改样式后请重新生成，测试会检查该文件是否为最新。

## 一轮怎么进行

1. 选择普通场（2 个 Bot）或繁忙场（20 个 Bot）。更换模式会重置场次与资金。
2. 每名参与者获得 1,000 模拟积分，另有独立做市账户初始储备 1,000；这些储备是真实记账的模拟资金。
3. 开始后共 60 秒，前 55 秒可以买卖、加热或降温；最后 5 秒封盘，交易和控场均停止。
4. 红色表示最终热度大于 102，黑色小于 98，绿色在 98 至 102 之间（含端点）。命中份额每份兑付 1 积分，其余兑付 0。持仓也可在封盘前提前卖出。
5. 每人每轮最多 3 张行动券，使用一张使热度 +1 或 −1。普通交易只改变报价和持仓，不直接改变热度。
6. 封盘后结算时加入本地模拟的整数环境扰动。范围是 ±（参与人数 × 3 + 3），覆盖全体可能的行动影响，避免合法行动把某个颜色变成必胜结果。它演示概率机制，不是可靠的链上随机源。
7. 结算后可继续下一轮，保留积分和累计表现；重置会恢复全部初始资金。

## 报价、收益和概率

市场使用三结果 LMSR 自动做市，价格随真实模拟订单变化。本地模式初始红、黑、绿价格分别为 0.45、0.45、0.10，价格之和为 1。链上 MON 合约仍使用自己的初始报价和独立账本。价格不是游戏胜率：热度与环境扰动产生的“情景概率”单独计算，并假设后续没有人继续行动。

本地订单支持“押中买入 / 做空 NO / 卖出 / 平 NO”。默认按 50 积分预算计算可成交整数份数（1–1,000），也可切换按份数交易。报价显示实际份数、未用预算、平均成交价、价格影响、0.3% 手续费和支出或到账；开仓预览显示命中兑付、净收益、收益率与含本金倍数。三色卡片按同一预算比较，报价会随其他成交改变。

做空红色即原子买入等量黑、绿份额：只要最终不是红色，每对组合兑付 1 积分；若红色命中则兑付 0。平 NO 同时卖出两腿，最多可卖份数为两色持仓较小值。每条腿实际扣费并记账，任一腿失败则整笔拒绝，没有借贷、杠杆或强平。它与永续合约做空的盈亏结构不同。

全部份额不会同时按屏幕上的边际价格成交。绿色初始更便宜，因此同样预算可获得更多份额、命中时回报更高，但价格不能证明实际胜率，也不会因为持有人少就自动获胜。这些新订单方式目前仅作用于本地积分，链上 MON 面板保持合约支持的买卖功能。

例如 100 份红色若平均成交价为 0.40，未计费用的成本是 40；红命中兑付 100，净收益 60。若提前以平均 0.65 卖出，未计费用的到账是 65。真实预览与记账还会扣除费用和考虑价格随数量变化。

市场账户承担做市盈亏并持有兑付资金。执行订单前核对余额、库存与兑付能力；无可接受报价时拒绝订单，不能承诺任何数量、任何时刻都能固定价格退出。每一笔交易和结算都保持参与者现金与做市现金总和守恒。份额是对这些储备的条件索取权，不能重复当作现金相加。

持仓采用平均成本计算已实现盈亏。账户净值与未实现盈亏按当前市场逐笔清仓估算，考虑价格影响和卖出费用，避免把自身买入抬价直接当成可兑现盈利；之后的交易和行情仍会改变结果。持仓明细中的市价估值若使用边际价格会另外标注。最大回撤使用相同清仓估值口径，未做盈利或策略平衡保证。

## Bot 和繁忙模式

动量 Bot 观察历史价格和当前趋势，概率 Bot 比较情景概率与市场报价。它们实际支付资金买入、卖出持仓、缴纳相同费用，并遵守余额、库存、封盘和行动券限制。策略不读取未来结算结果。

繁忙场运行 20 个本地策略账户，展示成交记录、持仓、盈亏和本地成交频率。浏览器按确定的模拟时序处理事件；它不是实际并行链上负载，也没有公开多人联机。利用 Monad 并行执行的多房间合约设计和真实网络基准测试属于后续工作。

## GitHub Pages 配置

已按用户授权启用 [Pages 自动部署工作流](.github/workflows/pages.yml)：每次推送 `main` 自动执行 `npm test`，测试通过后打包静态资源并发布到 [GitHub Pages](https://ailiheizi.github.io/blockpulse/)。测试失败时停止发布，线上保留上次成功版本；也可在 GitHub Actions 中手动运行该工作流。

工作流运行 `npm run build:pages`，把 `dist/` 的样式与脚本内联到 `_site/index.html` 后发布 `_site/`。浏览器只加载一个完整页面，避免新 HTML 混用旧缓存模块或样式导致界面失效；开发时仍保留 `dist/` 模块结构。构建不安装依赖，也无需运行 `server.mjs`。可在 [Actions 运行记录](https://github.com/ailiheizi/blockpulse/actions/workflows/pages.yml) 查看每次测试、构建和发布状态。
