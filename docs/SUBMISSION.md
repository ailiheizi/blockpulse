# BlockPulse · 独立事件预测交易竞技场

> 同一个盘口，多种交易方式；买卖改变价格，独立事件决定结果。

- 源码：<https://github.com/ailiheizi/blockpulse>
- 详细规则：[README](../README.md) · [项目说明](PROJECT.md)

## 项目简介

BlockPulse把预测份额交易做成短局竞技。玩家用模拟积分买入红、黑、绿结果份额，或买入NO做空某色，可在封盘前退出，或持有到独立事件结果确认。每份命中兑付1积分，其他0；本轮按扣除手续费后的净盈亏排名。

价格由三结果LMSR做市，随实际订单变化；每单可看均价、滑点、费用、条件兑付和回报倍数。竞猜结果、选入场价格和掌握退出时机共同影响成绩。少数一方可能因独立事件命中而逆转，但系统不会因为买的人少就让它获胜。

## 用户玩什么

1. 选预设：离线独立模拟，或真实SOL/USD价格事件。
2. 看规则：参考价、固定区间、截止和目标时间、结算来源提前公开。
3. 看报价：默认预算50积分，也可按份数。
4. 买入YES、卖出持仓、做空/买NO、平NO；练习场可启用自己的策略并查看实际决策和成交，真实行情暂不启用未校准自动交易。
5. 封盘后按事件结算，展示价格依据、持有人数、净盈亏与排名。

## 为什么改变了旧版玩法

早期“繁忙区块数量+行动让分”可受外部刷交易影响，也存在结果提前确定仍能开仓的边界。新版积分玩法明确分开价格形成与事件判定：订单不影响价格事件，移除行动券和让分，停用忙区块结算；引擎负责截止与已知结果保护。

公开可核对不自动等于不可操纵。当前真实来源为单一交易所公开行情，只保证本局订单不会改变该来源，不宣称生产级公平或已经完成链上预言机验证。

## 两种事件

**独立模拟练习**：60秒一轮，通常55秒开放交易。价格路径使用独立随机序列，交易、报价、Bot和玩家策略不能影响同一种子下的末价；本地合法剩余范围若提前确定结果则提前封盘。

**真实SOL/USD**：准备时读取Coinbase服务端时间，冻结最近完整一分钟K线的收盘参考价、±2基点（0.02%）上下界，以及未来约60–120秒的目标整分钟。目标前15秒停止交易，目标结束10秒后只读取精确目标分钟K线的close；未就绪或读取失败时保持等待/重试，不用最新ticker代替。

参考：[Coinbase K线字段与时间范围](https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/products/get-product-candles)。行情读数在浏览器中用于积分结算，尚无合约验签和多源仲裁。

## 与 Monad 的关系

当前保留Monad Testnet（chainId10143）的钱包、只读RPC和MON合约交易。旧合约每份命中兑付0.001MON，由钱包逐笔确认，支持部署或校验已有市场地址。它**尚未迁移**到新的独立价格事件规则，不能把积分新玩法描述为已由该合约结算。

后续工作是把固定事件规格、可信价格更新、交易截止、NO组合和兑付迁入合约；再由真实账户、房间和订单负载验证链上执行及并发。20个浏览器Bot与界面刷新频率均不是链上TPS证据。

## 技术与验证

前端为原生JavaScript/CSS，不安装运行依赖；引擎使用不可变状态更新和确定时序。资金以整数微积分记账，事件上下界采用整数微美元。源数据限定产品、精确时间窗口和价格格式；请求支持取消、超时和过期结果隔离。

`npm test`验证费用与资金守恒、NO两腿、策略、事件独立性、提前确定/截止边界、精确K线、异步取消、钱包与发布构建。真实RPC/行情连通性与浏览器流程另行验证，不以mock测试代替实网证明。需要本机anvil的合约集成测试在未安装时会明确跳过。

2026-10-17已完成系统Chrome的29项主流程检查及存档、离线单文件验收。真实事件界面的缺失数据/恢复结算场景使用mock控制；行情读取模块另经Coinbase公开API完成真实的准备、轮询及目标K线读取。尚无新价格事件的真实链上结算验收。

## 如何体验

打开演示链接，选择“模拟积分”，先在本地练习中完成一轮；真实SOL/USD需主动准备行情。需要钱包体验时选择独立MON合约入口。本地可双击根目录`本地试玩.html`，或`npm start`访问`http://127.0.0.1:4173`。

## 当前限制与后续

- 新玩法仍为浏览器内积分原型，无权威多人账本或资产托管；真实行情场次刷新丢失，旧控场存档不恢复。
- 单交易所行情存在可用性、数据修订和外部交易影响；没有把客户端格式校验等同于密码学证明。
- 既有MON合约使用区块哈希扰动，存在出块者影响及未经真实测试网验证的储备余额兼容性问题，详见README。
- 下一步是可验证价格结算合约、公开多人房间、策略账户、经过审核的事件模板，以及真实网络并发基准。
