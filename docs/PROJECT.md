# BlockPulse 项目说明

BlockPulse 是一个围绕未来事件交易的竞技原型。玩家买入红、黑、绿结果份额，行情随实际订单变化；可以在封盘前卖出，也可以持有到事件结果确定。每轮比较净盈亏，让判断、入场价格和退出时机都影响成绩。

## 玩家玩什么

1. 看清本轮事件，以及红、黑、绿的命中条件。
2. 用同一预算比较可买份数、含费用成本和命中净收益。
3. 押中买入，或用 NO 组合押某种结果不会发生。
4. 盘中卖出兑现，或等待结算。低价一方若最终命中，每份同样兑付 1，形成逆转；支持者少本身不会改变结果。

例如，100 份票若平均 0.10 买入，未计费用成本 10；若平均 0.30 卖出，到账 30；若持有且命中，兑付 100。实际报价还包含滑点与手续费，这只是计算示例。

## 当前已交付

| 能力 | 本地积分模式 | 测试网 MON 模式 |
| --- | --- | --- |
| 买入、卖出与动态报价 | 已实现 | 远端合约与界面已合并，需钱包和合约地址 |
| NO 做空、平 NO | 全额支付的两腿组合 | 暂未接入 |
| 按预算下单、同预算比较 | 已实现 | 按份数 |
| 控场 | 每人 3 张有限行动券 | 合约内热度行动 |
| 策略对手 | 2 / 20 个本地实际记账 Bot | 无自动 Bot |
| 结算来源 | 本地热度及模拟扰动 | 已有合约使用指定区块哈希扰动 |

两种模式资金独立。积分不能兑换；MON 使用测试网。新功能先在本地验证再逐步接入链上。

## 为什么适合区块链活动

目标事件来自公开区块数据，适合做高频状态更新、多人交易和可核验结算的演示。真正利用并行执行需要进一步把交易与事件结算接入合约并实测并发；20 个本地 Bot 不能作为链上吞吐证据。目前定位为游戏化事件预测与交易原型，未提供公开多人服务。
