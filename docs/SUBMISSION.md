# BlockPulse · 轮盘 × 多空交易 × 量化策略的事件游戏

> 把轮盘的揭晓悬念与交易所的多空交易、提前退出结合起来，让押注之后也有持续博弈。交易影响份额报价，独立事件决定最终颜色。

- **在线试玩**：<https://ailiheizi.github.io/blockpulse/>（打开即玩，无需安装和钱包）
- **源码仓库**：<https://github.com/ailiheizi/blockpulse>
- **详细规则**：[README](../README.md) · [项目说明](PROJECT.md)

## 一、项目简介

传统押注在选好一边之后，往往只剩等待结果。我们想保留红黑绿轮盘揭晓时的悬念和冷门反转，同时加入交易所的动态报价、多空选择和提前退出，再让量化策略参与其中，把等待变成持续做决策的过程。

BlockPulse 因此被做成短局事件交易游戏，本地练习每局 60 秒。当前每局围绕一个价格事件：开局时公开参考价和固定区间，玩家判断到期价格会落在区间上方（红）、下方（黑）还是区间内（绿），并买卖对应的结果份额，或买入 NO 押某色不会命中。

份额报价由自动做市根据实际积分订单变化。玩家可在交易开放期间卖出或平仓，按当时价格承担收益或亏损；也可以持有到期，每份命中兑付 1 积分，未命中兑付 0。每局按扣除手续费后的净盈亏排名，比拼判断、入场成本和退出时机。

### 趣味性来自哪里

- **下注之后仍有操作**：行情与报价变化时，继续持有、卖出、追加或买 NO 都是不同的选择；退出按市场报价成交，封盘后停止交易。
- **低价结果也可能反转**：低成本买入的结果最终命中，会产生较高的相对回报；冷门落空则该份额兑付为 0，系统不会因为人少而让它获胜。
- **手动判断与策略同场**：练习场可让自己的价值 / 动量策略实际下单，观察它与其他策略的交易如何改变市场报价。

项目源于一次临时灵感，是在黑客松期间快速完成的原型。当前希望先验证“轮盘悬念 + 交易选择 + 量化策略”是否好玩；更多事件主题和策略组合仍待完善。

## 二、设计理念：交易决定价格，事件决定结果

预测类游戏最怕结果被参与者左右。BlockPulse 把“价格形成”和“结果判定”彻底分开：

- **买卖只影响价格**：买入、卖出、做空都会改变份额报价和自己的盈亏，但不会改变事件本身。
- **结果来自独立事件**：结算依据是独立模拟路径的末价，或 Coinbase 指定分钟 SOL/USD 收盘价；本局下单数量、频率、Bot 和策略不会改变这一依据。单一外部行情源仍可能受外部市场交易影响。
- **规则开局即冻结**：参考价、区间、截止时间、目标时间和数据来源在开局前公开，之后不可更改。

早期版本曾用“Monad 繁忙区块数量”和行动券结算，我们发现外部刷交易就能抬高结果，于是移除了行动券和忙区块结算，改为独立价格事件。

## 三、怎么玩

1. **选事件**：本地模拟（离线、即开即玩），或实时 SOL/USD（联网读取真实行情）。
2. **看规则**：核对参考价、红黑绿区间、截止时间和结算来源。
3. **看报价**：默认每单 50 积分预算，也可按份数下单；下单前预览实际份数、均价、价格影响、0.3% 手续费、命中兑付和回报倍数。
4. **下单交易**：买入 YES 押某色命中，或买入 NO 押某色不会命中；交易开放期间可卖出或平仓，封盘后等待结算。
5. **到期结算**：按事件结果兑付，展示结算价格、区间、来源、持有人数和净盈亏排名。

## 四、两种事件

| 项目 | 本地模拟 | 实时 SOL/USD |
| --- | --- | --- |
| 数据 | 独立随机序列生成的模拟价格 | Coinbase Exchange SOL-USD 公开行情 |
| 参考价 | 模拟开局价 100 USD | 准备时最新完整一分钟 K 线的收盘价 |
| 区间 | 参考价上下各 0.02% | 参考价上下各 0.02%，开局冻结 |
| 交易时间 | 通常前 55 秒交易，最后 5 秒封盘；结果提前确定则提前封盘 | 目标时间前 15 秒封盘 |
| 结算依据 | 模拟路径的最后一个价格 | 目标整分钟 K 线的收盘价（约 60–120 秒后） |
| 联网 | 完全离线 | 需要联网，数据未就绪时等待重试 |

红：到期价格高于上界；黑：低于下界；绿：落在区间内（含两端）。实时事件只采用精确目标分钟的 K 线收盘价，不会用最新报价代替，也不会在数据缺失时随机补结果。

## 五、核心功能

| 功能 | 说明 |
| --- | --- |
| 动态做市 | 三结果 LMSR 自动做市，每笔成交都会改变报价 |
| 四种交易 | 买入 YES、卖出持仓、买入 NO 做空、平 NO，全部进入同一套做市和账本 |
| 无杠杆做空 | NO 是全额支付的两腿组合（如 NO 红 = 等量黑 + 绿），原子执行，无借贷、杠杆或强平 |
| 预算下单 | 按预算自动计算可买份数，同一预算下对比三色回报倍数 |
| 个人量化 | 练习场可开启价值 / 动量策略，设置每单份数、持仓上限和触发优势，用自己的积分买卖 YES 并展示理由；NO 由玩家手动操作，真实行情模式暂禁用自动交易 |
| 策略 Bot 同场 | 2 个或 20 个本地 Bot 实际出资、缴费、记账，不读取未来结果 |
| 真实账本 | 资金守恒，所有可能兑付都有储备覆盖；净值按含费用的实际清仓路径估算 |
| Monad 接入 | 多钱包连接、一键切换 Monad Testnet、实时区块监控、测试币水龙头汇总 |
| 链上 MON 交易 | 连接钱包，用测试网 MON 与链上 LMSR 市场合约直接交易 |
| 轻量部署 | 原生 JavaScript，无外部 SDK；单个 HTML 文件即可离线游玩；深浅主题切换 |

## 六、公平性保护

- **订单无法影响结果**：没有任何游戏内入口可以改变事件路径、区间或结算来源。
- **结果已知即停止交易**：本地模拟若在剩余时间内已不可能改变结果，会提前封盘；实时事件到达截止时间后，引擎层拒绝一切新订单（包括 NO 和平仓），不只依赖按钮禁用。
- **盈利不能“自己抬出来”**：账户净值按逐笔清仓、含费用的路径估算，自己买入抬高的价格不会算成已兑现利润。
- **策略不读未来**：Bot 和玩家策略只使用当前及历史信息，可能亏损，封盘时自动停止。

## 七、Monad 集成

- **钱包接入**：支持 EIP-6963 多钱包发现，兼容 `window.ethereum`；可一键添加并切换到 Monad Testnet（Chain ID `10143`），查看测试网 MON 余额。
- **实时区块监控**：无需钱包即可读取 Monad 测试网最新区块、出块时间和 RPC 延迟，每 5 秒采样一次。
- **测试币水龙头**：汇总 Monad 官方及 QuickNode、Alchemy 等第三方水龙头，连接钱包后一键复制地址。
- **链上市场合约**：`BlockPulseMarket.sol` 是共享的三结果 LMSR 市场，每份命中兑付 0.001 MON，手续费 0.3% 留在做市储备，做市储备始终覆盖所有可能兑付。页面可直接用钱包部署新市场，或校验并接入已有合约地址，再通过分享链接邀请他人进入同一市场。

当前链上合约仍运行早期规则（热度行动 + 区块哈希扰动），与新版积分玩法相互独立。下一步计划把独立价格事件、NO 组合和兑付逻辑迁入合约，实现链上结算。

活跃市场中的不同策略可能围绕报价和事件进展连续产生订单，这正是未来使用 Monad 承载频繁交易的应用方向。计划让真实账户在多房间运行策略，测量成交延迟与链上吞吐；当前 20 个本地 Bot 仅用于体验，尚未验证真实高并发能力。

## 八、技术实现与验证

- **前端**：原生 JavaScript ES Modules + CSS，无框架、无运行依赖；游戏引擎采用不可变状态更新和确定的时序。
- **精确记账**：资金以整数微积分记账，价格区间以整数微美元计算，避免浮点误差。
- **数据读取**：行情请求限定产品和精确时间窗口，支持取消、超时和过期结果隔离。
- **智能合约**：Solidity 0.8.30 + Foundry，含 13 项合约测试。
- **自动化测试**：103 项测试，覆盖费用与资金守恒、NO 两腿交易、策略、事件独立性、截止边界、K 线精确匹配、异步取消、钱包授权和构建产物。2026-10-18 本地运行结果为 102 项通过，1 项因未安装 Anvil 而跳过。
- **持续发布**：每次推送 `main`，GitHub Actions 先跑测试，通过后打包成单个 HTML 发布到 GitHub Pages；测试失败则不发布。

## 九、如何体验

1. 打开在线试玩地址，选择“模拟积分”和“本地模拟”，点击开始，体验一局完整的交易和结算。
2. 选择“实时 SOL/USD”并主动准备行情，用真实价格事件再玩一局。
3. 想体验链上交易，切换到“测试网 MON”，连接钱包、领取测试币，再部署或接入市场合约。

本地运行：克隆仓库后双击根目录的 `本地试玩.html` 即可离线游玩，或执行 `npm start` 后访问 `http://127.0.0.1:4173`。

## 十、当前限制

- 模拟积分和测试网 MON 都没有现实价值，两套账本互相独立，不构成任何收益承诺。
- 新版积分玩法在浏览器内运行，尚无服务器权威账本、公开多人房间或资产托管；实时行情场次刷新页面后不保留。
- 实时事件依赖单一交易所的公开行情，存在可用性、数据修订和外部市场影响的风险，尚未接入经合约验证的价格预言机。
- 链上合约的结算噪声取自区块哈希，出块者可施加影响，仅适合测试网演示；Monad 储备余额规则对合约账户的影响尚未在真实测试网验证。
- 20 个 Bot 运行在本地浏览器中，不代表链上吞吐或 TPS。

## 十一、后续规划

愿景是“找到一个有趣且结果可核对的事件，就能用这套系统游玩”。目前只支持本地模拟价格与真实 SOL/USD 两个预设，用户尚不能任意创建事件。扩展模板时，需要先固定数据源、三个互斥且覆盖全部有效结果的选项、交易截止、结果确认时间，以及数据缺失或事件取消时的处理规则。

- 把独立价格事件、NO 组合、交易截止和兑付迁入合约，接入可验证的价格数据，实现链上结算。
- 推出经过审核的事件模板，支持按模板创建房间；价格之外的赛事胜 / 负 / 平、降雨量区间等仅为未来玩法例子，尚未接入。
- 上线公开多人房间和撮合服务，利用 Monad 的高性能支持多房间并发，并进行真实网络基准测试。
- 开放链上策略账户，让玩家的量化策略成为真实的链上参与者。
- 探索更多策略组合、仓位控制和对局节奏，让玩家在持有、退出与反向判断之间作出更多选择，同时保留事先公开的事件结算规则。
