# BlockPulse 项目说明

BlockPulse 是一个围绕未来事件交易的竞技原型。玩家买入红、黑、绿结果份额，行情随实际订单变化；可以在封盘前卖出，也可以持有到事件结果确定。每轮比较净盈亏，让判断、入场价格和退出时机都影响成绩。

## 玩家玩什么

1. 看清本轮事件，以及红、黑、绿的命中条件。
2. 用同一预算比较可买份数、含费用成本和命中净收益。
3. 押中买入，或用 NO 组合押某种结果不会发生。
4. 盘中卖出兑现，或等待结算。低价一方若最终命中，每份同样兑付 1，形成逆转；支持者少本身不会改变结果。

例如，100 份票若平均 0.10 买入，未计费用成本 10；若平均 0.30 卖出，到账 30；若持有且命中，兑付 100。实际报价还包含滑点与手续费，这只是计算示例。

## 当前已交付

| 能力 | 本地积分模式 | 测试网 MON 模式 |
| --- | --- | --- |
| 买入、卖出与动态报价 | 已实现 | 远端合约与界面已合并，需钱包和合约地址 |
| NO 做空、平 NO | 全额支付的两腿组合 | 暂未接入 |
| 按预算下单、同预算比较 | 已实现 | 按份数 |
| 控场 | 每人 3 张有限行动券 | 合约内热度行动 |
| 策略对手 | 2 / 20 个本地实际记账 Bot | 无自动 Bot |
| 玩家量化 | 可配置价值 / 动量策略，实际扣费成交 | 暂未接入 |
| 结算来源 | 本地目标区块模拟 / 真实 Monad 目标块笔数 | 已有合约使用指定区块哈希扰动 |
| 净盈亏排名 | 按真实积分账本计算，支持并列 | 当前按链上持仓与交易展示 |

两种模式资金独立。积分不能兑换；MON 使用测试网。新功能先在本地验证再逐步接入链上。

## 两种事件，完成同一交易闭环

**本地练习**：60 秒一轮，目标为模拟第 120 块交易笔数，红 >102、黑 <98、绿 98–102。前 55 秒可以买卖；有限控场改变流量预期但不能确定结果。开始时绿票低价，若买后价格上涨可以提前卖出，若最终命中每份兑付 1。逆转来自实际结果与成交价格，系统不会为了刺激玩家篡改结果。

**真实 Monad 事件**：以开局前读取的高度 H 为起点，固定 H+150 为目标区块、H+130 为区块截止。最近 8 块确定公开上下界；55 秒或截止块先到就封盘，目标块确认 2 块后按精确交易笔数结算。失败保持等待，可重试。本地操作不制造链上交易，真实模式不显示未经校准的概率。

**自己的量化**：价值 / 动量策略用玩家自己的余额和库存，显示每次决策理由与成交。可以手动停止，封盘自动停止；真实事件没有校准模型时观望。

本轮按净盈亏排名，包含提前退出收益、到期兑付和全部费用。结果展示目标、来源、交易笔数、区间与实际持仓账户数（含 Bot），不会把“买的人少”当作概率。

## 一局以什么为事件

第一版固定为“指定未来区块的交易笔数”，玩家选择押哪种结果，也可选择本地练习或真实 Monad 数据。当前没有任意文字创建赌局，也没有多事件列表。

后续按“预设事件列表 → 按模板创建房间”扩展，例如未来一段时间交易总量、目标区块 gas 使用量。每个模板必须预先固定数据源、截止条件、区间和结算规则；用户选择参数，系统据此生成可核验的事件。

## 为什么适合区块链活动

目标事件来自公开区块数据，适合做高频状态更新、多人交易和可核验结算的演示。真正利用并行执行需要进一步把交易与事件结算接入合约并实测并发；20 个本地 Bot 不能作为链上吞吐证据。目前定位为游戏化事件预测与交易原型，未提供公开多人服务。
